## LED 전원: 수정이 필요한 핵심 항목

64키 RGB code 5는 PWM 합계 960으로 현재 1020 제한보다 낮다. 하지만 최대 채널전류 14.5 mA를 적용하면 동시 점등 구간의 키 LED 전류는 **2.784 A**, 전형적 1 kHz에서 점등시간은 **19.61 µs**다. 평균전류 제한만으로 순간 부하를 해결할 수 없다.

아래는 공급 4 V, 전류제한 174 mA, 경로저항 0.2844 Ω, LED 대기전류 44.4 mA typical, ESR 5 mΩ, 모든 키의 PWM 위상이 같은 경우다. 3.7 V에 처음 도달하면 계산을 종료해 LED를 규격 이하에서 정전류 부하로 계속 외삽하지 않았다.

| 유효용량 | 3.7 V 아래로 내려가기까지 | 판정 |
|---:|---:|---|
| **8.9 µF — 현재 부품의 가정값** | **0.918 µs** | 점등 구간을 지지하지 못함 |
| 12.5 µF — 명목 합계 가정 | 1.289 µs | 지지하지 못함 |
| 47 µF — 가상 변경 | 4.847 µs | 지지하지 못함 |
| 100 µF — 가상 변경 | 10.313 µs | 지지하지 못함 |
| 220 µF — 가상 변경 | 이 조건의 점등 구간 유지 | 최저 3.737 V |
| 470 µF — 가상 변경 | 이 조건의 점등 구간 유지 | 최저 3.863 V |

전체 1,620개 민감도 조건 중 467개가 3.7 V 조건을 벗어났다. 위상을 고르게 분산하면 결과가 달라지지만 해당 LED가 그런 위상 분산을 보장하지 않는다. PWM 1 kHz는 typical이며 보장 범위가 없다. 500/2,000 Hz는 민감도 가정이다. 더 큰 용량은 실장된 부품이 아니고, 용량 증가에는 기동·돌입전류·제한기 동작 재검토가 필요하다. 여기서 부품값 변경을 승인하거나 선택하지 않았다.

이 모델은 이상적인 즉시 전류제한, 집중정수 커패시터, 64개 키의 RGB 피크를 사용한다. 언더글로우는 꺼져 있고 대기전류만 포함한다. 실제 분산 커패시터/배선/제한기 응답/LED PWM 위상을 포함한 검증으로 확장해야 한다.

## LED 신호와 누화

초기 810개 해석은 수치 오류 없이 완료됐다. 773개는 설정한 문턱값·펄스폭 조건을 만족했고 37개는 문턱값 재교차가 발생했다. **37개 모두 10 Ω / 1 ns / 5 pF 출력 가정**이었다. 20 Ω / 2 ns부터 더 느린 네 가정에서는 초기 검사상 해당 위반이 없었다. 37개는 모두 펄스폭 자체의 계산 여유가 양수였으며, 링잉의 재교차 때문에 표시됐다.

경고 37개와 대조군 4개를 최대 시간 간격 0.2 ns → 0.025 ns, `reltol=1e-4`로 재검사했다. **35개 경고가 남았고 KEY_RGB_CHAIN_23의 두 조건은 판정이 바뀌었다.** 이 두 조건은 수치 민감성이 있어 확정적인 물리 합격/불합격으로 사용하지 않는다. 이는 시간 간격 검사이며 2 mm LC 분할의 공간 수렴이나 실제 IC 입력 필터 검증은 아니다.

MCU → SN74LV1T125 → 330 Ω → 첫 LED까지 별도 검사했다. 초기 12개 중 키 체인의 전형적 버퍼 가정 두 조건에서 재교차가 표시됐다. 0.025 ns 재검사에서도 두 조건 모두 재교차가 남았다. 결과는 `led/first-refinement.json`과 `summary.json`에 기록했다. 문턱값 재교차가 즉시 실제 비트 오류를 뜻하지는 않지만, 이를 무시하고 합격 처리하지 않았다.

현재 배선의 매트릭스 인접 구간 네 곳에서 실시한 누화 24개 조건은 설정한 문턱값을 유지했다. 최소 여유는 **0.796 V**였다. 서로 다른 구간을 최소 간격의 균일한 결합 선로로 바꾼 민감도 모델이다. 모든 공격 신호의 동시 전환, 내부층의 정확한 기준면, 3D 전자기장까지 포함하지 않는다.

실제 LED 출력 임피던스·상승시간·입력 클램프 모델이 없고, 역실장 LED의 5 V 시험 문턱값 비율을 4 V에 적용했다. 내부층은 0.2104/1.065 mm의 균일 기준면 거리를 가정했으며 엄밀한 상·하한이 아니다. 클램프 없는 모델의 수 V 오버슈트는 실제 핀 전압 예측값으로 사용할 수 없다. **현재 RGB qualification = 0을 유지한다.**

## USB, 키 입력, 크리스털, 기타 신호

- USB PCB 지연은 **0.4184 ns / 1 ns 기준**. 유전율 3.8–5.0 가정에서는 0.4128–0.4242 ns였다. 명목 주 배선 차동임피던스는 약 95.1 Ω이다.
- USB 50 pF 시험 부하에서 4/8/16 ns 입력 램프의 평균 10–90% 에지는 약 4.75/7.19/13.09 ns였다. 가장 빠른 호스트 가정에는 링잉이 남는다. 수신단과 50 pF 송신 시험점의 기준을 혼용해 전체 PASS로 표시하지 않았다.
- 기존 USB 측정기는 낮은 레벨의 링잉과 다음 데이터 에지를 연결해 약 29 ns 같은 잘못된 평균을 만들었다. 동일한 50% 교차점을 중심으로 10/90% 교차를 짝지어 수정하고 합성 링잉 회귀 검사 후 다시 실행했다. 캡처 시작에서 잘린 일부 에지는 `unpaired_edges`로 남긴다. 실제 USB 인증 측정은 별개다.
- 매트릭스 최악 선택 안정화 **236.8 ns / 설정 800 ns**, 해제 안정화 **4.16 µs / 설정 30 µs**. 60°C 누설전류 외삽에서는 61개 다이오드의 고레벨 강하 0.648 V / 허용 1.3 V였다. 온도별 다이오드·GPIO 모델은 일부 가정이다.
- 현재 fresh netlist와 24개 GPIO 매핑을 검사했고, 두 firmware 배열의 이상 다이오드 모델에서 빠진 키·고스트가 없었다. 조합 1–3개와 전체 누름/뗌을 검사했으며 모든 2^60 부분집합을 탐색했다고 주장하지 않는다.
- QSPI 현재 25 MHz 읽기 설정의 단순 지연 예산 여유는 **13.64 ns**. 미사용 75 MHz 가정의 여유는 0.30 ns에 불과하며 해당 속도를 승인하지 않는다. 이 계산은 입력 setup/hold·지터·IBIS 분석을 대체하지 않는다.
- 크리스털 부하·기생용량 가정에 따른 주파수 당김은 −4.9…+36.3 ppm. worst 가정에서 ESR의 5배 음저항은 `gm ≥ 1.5 mS`일 때 얻어졌다. RP2350의 실제 gm을 확인하지 못했으므로 기동 보장이 아니다. 가정한 구동 전력은 최대 178.2 µW / 부품 200 µW 한도였고 구동 여유가 큰 편은 아니다. 전압·온도별 기동과 실제 drive level 확인이 필요하다.
- SWD, RUN, BOOTSEL, 확장 GPIO의 RC·누화·전압 계산은 `signal/misc.json`에 있다. 그 파일의 단순 ESD 전류 비교는 IEC 면역성을 입증하지 않는다.

## 전원 트리와 이상 조건

fresh netlist의 부품 정체성을 확인하고, 현재 후보의 DC 구리 저항을 전원 모델에 넣었다. 30회 실행 모두 유한한 파형과 정상 시뮬레이터 종료를 확인했다. 이는 **30개 전기 합격 판정**이라는 뜻이 아니다.

- 5/5.5 V 투입 시 +4 V가 3.9 V에 도달하는 시간 약 36 ms, +3V3가 3.135 V에 도달하는 시간 약 33.3 ms. 입력 피크 약 4.06/4.46 A는 지정한 이상 전압원·케이블·입력 커패시터 모델의 짧은 돌입전류이며 실제 USB 호스트 능력을 가정한 값이 아니다.
- +3V3 20→120 mA 부하 변화의 강하는 약 14 mV. LED drive 0→58 mA 변화에서 +4V_LED 강하는 스위칭 모델 약 24 mV. **이 결과는 동기 PWM의 2.784 A 펄스를 검증하지 않는다.**
- 실제 C143 = 22 pF를 사용한 루프 모델의 위상 여유는 49.1–53.2°. C143 미실장/47 pF는 비교용 가상 조건이다. 공급사 제어기 모델이나 실제 주파수 응답 측정은 아니다.
- LED 단락의 지속전류는 약 201 mA. 충전된 LED 레일에 이상적인 저저항 단락을 넣으면 커패시터 방전 피크가 약 40 A로 계산된다. 단락 ESL·접촉저항·전류분배를 생략했으므로 실제 피크 정격 판정값으로 사용하지 않는다.
- 저전압에서는 레귤레이터 드롭아웃과 재시작이 발생했다. 6 V 운전 중 서지 조건에서는 +3V3가 1.5 V까지 내려갔다가 회복했다. 전원 유지가 보장된다는 결과가 아니다.
- 6/20 V 잘못된 입력, 입력 스너버 미실장 비교를 실행했다. 이 가상 조건은 커넥터·TVS·커패시터의 과전압 생존 보증이 아니다. 예를 들어 20 V 입력/스너버 미실장 모델은 eFuse 입력 약 30.85 V를 보여 준다.

실행 원본 `power/raw-results.json`과 그림에는 상속된 `150mA` 라벨이 남아 있다. 실제 보존 deck의 `iled=0.058`이며 대기전류는 별도 44.4 mA다. **`power/corrected-results.json`은 수치를 바꾸지 않고 라벨만 바로잡은 보고서**다. 현재 wrapper도 다음 실행부터 올바른 라벨을 쓰도록 수정했다. 실행 당시 wrapper는 `source-at-power-run/`에 원래 해시 그대로 보관했다.

전원 모델은 공급사의 암호화 macro가 아닌 행동 모델이다. 가지별 구리 저항은 현재 후보를 쓰지만 공유 경로, 접지 임피던스, 기생 인덕턴스는 근사다. 유효 커패시턴스, buck 효율/PFM, AP2112 실제 주파수 응답 및 U7/U8의 열 차단·재시도는 충분히 검증되지 않았다. **U7은 latch-off TPS2553-1이 아니다.**

## 열: 정상상태와 단락의 차이

66개 창과 드릴을 제거한 PCB 재료 형상에 2D 면내 전도와 양면의 유효 열전달을 적용했다. 면 전도도 0.004/0.010/0.020 W/K, 면당 열전달계수 2/5/10 W/m²K를 가정했다. 정확한 구리 적층·케이스 접촉·패키지 접합온도를 재현한 모델이 아니다.

| 부하 | 중간 방열 가정의 온도 상승 | 전체 방열 가정 범위 |
|---|---:|---:|
| LED off, 3V3 60 mA | 약 11.7°C | 5.9–29.3°C |
| LED rail 평균 102.4 mA, 3V3 60 mA | 약 13.3°C | 6.7–33.3°C |
| LED rail 128 mA 가정, 3V3 120 mA | 약 25.1°C | 12.5–62.7°C |
| LED rail 234 mA DC, 3V3 120 mA | 약 26.8°C | 13.4–66.9°C |
| U7 단락 제한전류가 계속 흐르는 가상 상태 | 약 85.3°C | 42.6–213.2°C |

표는 주변온도에 더하는 PCB 온도 상승이다. 마지막 줄은 열 차단을 생략한 **지속 발열 what-if**이고 실제 칩이 그 온도까지 정상 동작한다는 예측이 아니다. 고온에서 선형 물성이 유지된다는 주장도 아니다. 정상 부하의 전체 가정 범위도 온도 보장이 아니다.

1/0.5 mm 격자의 최대 피크온도 차이 약 1.13°C, 최대 상대 차이 약 3.13%. 에너지 수지 오차는 약 1.7×10^-12 W 이하. 30초 간격의 backward Euler로 1시간 과도 응답을 계산했다. 3V3 전체 전력을 U1에 집중하고 LED는 균등 분배했으며 buck 효율은 90% 가정이다. 일부 작은 보호소자·구리 손실과 패키지 열저항은 생략했다. 한 개 레퍼런스의 대체 위치 두 곳에 열을 중복 분배하던 초안은 폐기하고 네 실장 조합을 분리해 다시 계산했다.

## 이번 결과로 처리하지 않은 범위

- 실제 LED PWM 위상/주파수·대기전류 최대치, 입력 필터·클램프·출력저항 측정.
- 정밀 PDN 임피던스, 전원/접지 공통 임피던스, 제조사 IBIS와 3D 전자기장, 방사/전도 EMI, IEC ESD 및 USB 인증.
- 실제 케이스 경계조건을 이용한 CFD/패키지 접합온도, 온도에 따른 열 차단/재시도.
- PCB 구멍 주변 휨·피로·충격 FEA, 실제 스위치/스테빌라이저/소켓의 공차 조합과 체결력. 기존 명목 치수/DRC 검사는 이들을 대신하지 않는다.
- 실장 업체의 역실장·급지 방향·paste·창 가공공차·MSL 검토, 새 제조 데이터 export/readback.
- 전체 QMK/ARM 빌드, 실제 VIA 앱, 실물 키보드·USB 호스트 검증. 이번 portable PASS는 해당 항목을 포함하지 않는다.

과거 `simulate_power.py`, `simulate_thermal.py`, `analyze_power.py`는 이전 LDO/LED/리미터 가정을 포함해 그대로 적용하지 않았다. 과거 고속 USB FFT 모델은 RP2350의 FS 동작 판정을 대신하지 않는다. 기존 `sim_led.py` 전체 실행의 구형 부품 보호 검사는 우회하지 않았으며, 핀 정의가 맞는 새 혼합 LED 분석을 별도로 만들었다.

## 재현성과 변경 이력

`summary.json`, `manifest.json`, `raw-artifacts.json`, `COMMANDS.md`를 함께 읽는다. 결과 JSON, 실행 deck 압축본, 입력 netlist, 도구 snapshot과 소형 그림은 이 디렉터리에 있다. 대용량 파형은 `build/bottom-sim-20261114/`의 해시 목록에 지정된 파일로 보존했다.

이번에 배선 추출기가 패드 가장자리·트랙 둥근 끝의 실제 접촉을 놓치는 오류를 수정했다. 새로운 추출로 USB/매트릭스/기타 신호/크리스털을 다시 실행했다. 크리스털 AC 두 조건의 파일명도 구분해 원시 결과가 덮어써지지 않도록 했다. 기존 `../verification-manifest.json`은 당시의 도구와 보고서에 대한 **역사적 기록**이며, 현재 수정된 도구의 해시와 동일하다고 취급하지 않는다. 새 시뮬레이션 해시는 이 폴더의 manifest가 담당한다.

기존 PCB 해시의 native DRC 0 / opens 0 / ERC 0, 274 net 연결성 결과는 그대로 유지된다. 이 결과와 시뮬레이션을 합쳐도 위 LED 문제·실측·제조 조건이 닫히기 전에는 제조 승인할 수 없다. PCB 승격, 주문 패키지 export, commit/push/merge는 하지 않았다.
